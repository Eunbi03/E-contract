1. 전체 흐름 한눈에 보기

자동 발송·백업

근로자가 서명을 제출해도 자동으로 끝나지 않으며, 관리자가 승인 버튼을 눌러야 계약이 완료됩니다.

핵심만 기억하면: 관리자가 할 일은 ①작성해서 보내기, ②근로자가 서명하면 내용 확인 후 승인 버튼 누르기, 이 두 가지입니다. 나머지(링크 발급, 알림 발송, 문서 보관)는 전부 시스템이 자동으로 처리합니다.

2. 시작하기

  • 접속 주소는 Apps Script에 배포된 고정 웹앱 링크입니다. 자주 쓰므로 브라우저 즐겨찾기에 등록해 두는 것을 권장합니다.
  • 이 주소를 열면(파라미터 없이) 비밀번호 입력 화면이 먼저 뜹니다. 맞게 입력해야 "고용주 근로계약서 작성" 화면으로 들어갈 수 있습니다. 근로자가 서명을 마친 뒤 열게 되는 승인(직인 날인) 화면도 마찬가지로 비밀번호를 먼저 입력해야 합니다 — 근로자에게 가는 링크(서명용 접속 링크, 완료 후 다운로드 링크)는 비밀번호 없이 그대로 열립니다.
  • 비밀번호는 이 설명서에 적어두지 않습니다. 모르면 비밀번호를 설정해둔 담당자나 개발자에게 문의해 주세요.
  • 비밀번호를 바꾸고 싶으면, 로그인 후 "관리" 탭(작성/수정/설정 탭 옆)에서 변경할 수 있습니다. 기존 비밀번호를 한 번 더 입력해야 바뀝니다 — 기존 비밀번호를 모르면 바꿀 수 없으니(개발자가 Apps Script 쪽에서 직접 재설정해야 함), 바꾼 비밀번호는 안전한 곳에 따로 기록해 두세요.
  • 화면 구성: 왼쪽은 입력 사이드바(작성/수정/설정/관리 탭), 오른쪽은 지금 작성 중인 계약서가 실시간으로 그대로 미리보기 됩니다.

3. 계약서 작성 및 발송 — 작성 탭

왼쪽 사이드바 "작성" 탭에서 아래 순서로 입력합니다.

  1. 계약 법인 — 드롭다운에서 선택 (목록은 설정 탭에서 관리, 7장 참고)
  2. 입사일
  3. 계약 형태
    • 정규직 / 계약직 중 선택
    • 계약직 선택 시: 계약기간(3개월/6개월/1년/직접입력) 및 종료일 지정
    • "수습 적용" 체크 시: 수습 시작일·개월수(종료일 자동 계산)와 수습급여 입력
  4. 근무장소 및 업무
    • 근무장소는 직접 입력
    • 담당업무는 사무직/영업직/생산직 중 선택하거나 "직접입력"으로 자유 입력
  5. 근로·휴게시간
    • 1일 근로시간, 주 근무일수, 시업~종업 시각
    • 휴게시간(총 분 + 시작~종료 시각)
    • 주마다 근무시간이 달라지는 경우 "격주" 체크박스를 켜면 표 형식이 아니라 자유 텍스트(1주차/2주차 내용 등)로 직접 입력할 수 있고, 입력한 내용이 계약서 표에 그대로 출력됩니다.
  6. 근로자 발송 정보
    • "+ 근로자 추가" 버튼으로 한 번에 여러 명을 등록해 동시에 발송할 수 있습니다.
    • 근로자 카드마다 개별로:
      • 발송 방식: 이메일 또는 문자 중 선택 (이 선택이 나중에 승인 완료 안내도 같은 방식으로 나가는 기준이 됩니다 — 5장 참고)
      • 성명
      • 전화번호 — 근로자가 링크 접속 시 본인인증 비밀번호로도 그대로 사용되니 정확히 입력해야 합니다 (하이픈은 자동으로 붙습니다)
      • 이메일 (이메일 발송 모드를 선택했을 때만 입력란이 보임)
    • 근로자가 2명 이상이면 각 카드 우측 상단의 × 버튼으로 삭제 가능
  7. 입력을 마쳤으면 "발송하기" 클릭 → 확인창에서 한 번 더 확인 → 발송 실행

발송 후 뜨는 안내 팝업 읽는 법

  • "발송 완료! (총 N명)" — 전원 정상 발송
  • "⚠ 발송 실패 있음" — 일부 또는 전부 실패. 몇 명이 실패했는지 뜨며, 정확한 사유는 구글시트의 "발송큐" 시트 → "실패사유" 열에서 바로 확인할 수 있습니다 (4장 참고).
  • "발송 시작됨: 총 N명 중 M명 즉시 발송 완료, 나머지는 순차 발송" — 한 번에 여러 명(기준: 30명 초과)을 보내면 처음 일부만 즉시 발송되고, 나머지는 시스템이 자동으로 몇 분 간격을 두고 이어서 발송합니다. 기다리면 알아서 다 나가므로 별도 조치가 필요 없습니다.

4. 근로자 진행 상황 확인하기

이 시스템은 구글 스프레드시트를 데이터 저장소로 함께 씁니다. Apps Script 웹앱 화면이 아니라 원본 구글시트 파일(11장 참고)을 열면 아래 시트들로 진행 상황을 추적할 수 있습니다.

시트 이름의미관리자가 할 일
발송큐방금 보낸(또는 보내는 중인) 발송 건들의 상태상태 열이 FAILED면 "실패사유" 열 확인 후 재발송 여부 판단
계약대기근로자가 아직 서명하지 않은 계약서 원본 데이터직접 건드릴 필요 없음 (내부 데이터)
승인대기근로자가 서명을 제출 완료했고, 관리자 승인을 기다리는 건주기적으로 확인! E열 "승인링크"를 눌러 승인 진행 (5장)
계약목록관리자 승인까지 끝나 최종 완료된 계약서 목록"문서링크" 열로 언제든 완료본 재열람 가능
⚠️ 중요 근로자가 서명을 제출해도 관리자에게 자동으로 알림이 가지 않습니다. "승인대기" 시트를 주기적으로 새로고침해서 새로 올라온 건이 있는지 직접 확인하는 습관이 필요합니다. (알림 자동화가 필요하면 개발자에게 문자·메일 알림 추가를 요청할 수 있습니다.)

이 시트들은 시스템이 자동으로 읽고 쓰는 "데이터베이스" 역할이라, 특별한 이유 없이 셀 값을 손으로 직접 고치는 것은 권장하지 않습니다(특히 ID·상태 열). 내용을 바꾸고 싶으면 가능한 한 작성/수정/설정 탭을 통해서 하는 것이 안전합니다. 다만 "발송큐"의 실패사유 확인, "승인대기"·"계약목록"의 링크 클릭처럼 읽기 용도로 보는 것은 언제든 괜찮습니다.

5. 최종 승인 (직인 날인)

  1. "승인대기" 시트에서 승인하려는 행의 E열(승인링크)을 클릭합니다.
  2. 근로자가 작성·서명한 계약서 전체 내용이 그대로 보입니다 (이 화면에서는 수정 불가 — 확인 전용입니다).
  3. 내용에 문제가 없으면 "승인 및 직인 날인" 버튼 클릭 → 확인창 → 승인.
  4. 승인되면 자동으로 아래 일이 한 번에 처리됩니다.
    • 계약서에 해당 법인의 직인 이미지가 날인됩니다.
    • 근로자에게 완료 안내가 최초 발송 때 썼던 방식(문자였으면 문자, 이메일이었으면 이메일)으로 자동 발송되며, 완료된 계약서 열람·PDF 다운로드 링크가 포함됩니다.
    • 완료된 계약서가 Drive에 자동 백업됩니다.
    • "계약목록" 시트에 기록되고, "승인대기" 시트에서는 사라집니다.

직인이 안 찍히고 경고가 뜨는 경우

"직인 없이 저장됩니다"라는 alert가 뜨면, 메시지에 구체적인 사유가 함께 표시됩니다. 가장 흔한 원인은 법인명 철자 불일치입니다 — "회사설정" 시트의 법인명과 Apps Script의 Seals.html에 등록된 직인 이미지 키가 띄어쓰기·괄호 하나까지 정확히 같아야 합니다(예: (주)와 ㈜는 다른 글자로 취급됩니다). 13장 FAQ도 함께 확인하세요.

6. 완료된 계약서 확인·다운로드

  • "계약목록" 시트의 "문서링크" 열을 클릭하면 완료된 계약서를 언제든 다시 열어볼 수 있습니다.
  • 계약서 화면에서 "PDF 저장" 버튼을 누르면 브라우저 인쇄 기능으로 PDF 저장이 가능합니다.
    • 카카오톡·네이버 등 인앱 브라우저에서는 PDF 저장이 막혀 있을 수 있습니다 — 이 경우 Safari나 Chrome 같은 일반 브라우저로 링크를 다시 열어달라고 안내해 주세요.
  • 근로자도 완료 안내 문자·메일로 받은 링크에서 동일하게 다운로드할 수 있으며, 승인일로부터 3개월간 다운로드가 가능하도록 안내 문구에 명시되어 있습니다.

7. 설정 탭 — 계약 법인 관리

  • "+ 법인 추가"로 새 법인을 등록하고, 각 법인 카드의 "수정"/"삭제"로 관리합니다.
  • 입력 항목: 법인명, 주소, 전화번호, 대표자, 담당자명, 담당자연락처, 담당자이메일
  • 법인명은 계약서에 그대로 출력되고 직인 매칭 기준으로도 쓰이므로 정확히 입력해야 합니다.
⚠️ 법인명을 바꿔도 이미 발송·진행 중인 계약서에는 영향이 없습니다(그 시점 데이터는 이미 저장되어 있음). 다만 Seals.html에 등록된 직인 이미지 키도 새 법인명에 맞게 함께 바꿔야 앞으로의 승인 건에 직인이 계속 찍힙니다 — 이 파일 수정은 Apps Script 코드 영역이라 개발자 문의가 필요합니다.

여기 등록한 "담당자연락처"는 문자 발송 시 발신번호로도 함께 쓰입니다. 새 번호를 등록했다면 그 번호가 Solapi(문자 발송 서비스) 콘솔에 발신번호로 사전 인증되어 있는지 확인이 필요합니다(최초 1회, 개발자 영역).

8. 설정 탭 — 새 계약서 초기값

  • 작성 탭에서 새 계약서를 시작할 때 기본으로 채워지는 값(근무장소, 담당업무, 근로시간, 휴게시간 등)을 미리 지정해둘 수 있습니다.
  • 자주 쓰는 조건이 있다면 여기 미리 입력해두면 작성 탭에서 매번 다시 입력할 필요가 없습니다.
  • 여기서 값을 바꿔도 이미 작성 중이거나 발송된 계약서에는 영향 없고, 그다음 "새로" 작성을 시작하는 계약서부터 적용됩니다.

9. 설정 탭 — 발송 메시지(문자·이메일) 문구 수정

  • 작성 탭에서 "발송하기"를 눌렀을 때 근로자에게 나가는 문자/이메일 본문(이메일은 제목 포함)을 직접 고칠 수 있습니다.
  • 왼쪽의 변수 블록(근로자명, 법인명, 링크, 담당자명, 담당자연락처, 담당자이메일 등)을 본문 안으로 끌어다 놓으면, 실제 발송 시 해당 값으로 자동 치환되는 "칩"으로 들어갑니다.
  • 칩을 지우는 방법 3가지: 칩의 × 클릭 / 칩 옆에서 백스페이스 / 칩을 바깥 "변수 블록" 영역으로 다시 끌어다 놓기
  • 문자(SMS)는 제목이 없는 형식이라 본문 내용만 사용됩니다.
  • 저장하면 그 이후의 모든 발송부터 새 문구가 적용됩니다(이미 나간 메시지는 영향 없음).
ℹ️ 참고 승인(직인 날인) 완료 시 근로자에게 나가는 "완료 안내" 문구는 이 화면에서 수정되지 않습니다. 현재는 코드에 고정 문구로 들어 있습니다 — 바꾸고 싶으면 개발자에게 요청해 설정 탭으로 뺄 수 있습니다.

10. 수정 탭 — 계약서 조항 문구 수정

  • 오른쪽의 실제 계약서 미리보기를 보면서 그 자리에서 바로 수정하는 방식입니다.
  • 왼쪽에서 수정하고 싶은 조항·동의서 버튼을 클릭하면, 오른쪽 해당 부분이 바로 편집 가능한 상태로 바뀝니다.
  • 제목·본문을 자유롭게 고칠 수 있고, 해당 조항에 맞는 변수 블록(근무장소, 담당업무 등)이 있다면 끌어다 넣을 수 있습니다.
  • 수정 후 "OO조 저장" 버튼으로 저장, "편집 종료"로 편집 모드를 닫습니다.
  • 저장하면 그 이후 새로 작성되는 계약서부터 반영됩니다(이미 발송됐거나 서명 진행 중인 계약서에는 영향 없음).

수정 탭에서 고칠 수 있는 부분

제1조(목적), 제3조(근무장소), 제4조(담당업무), 제5조(임금), 제7조(휴일 및 휴가), 제8조(근로계약의 종료 등), 제9조(의무), 제10조(손해배상), 제11조(기타 근로조건), 그리고 전자계약 동의서 3종(전자계약 체결 동의서 / 연장·야간·휴일근로 동의서 / 동의 및 교부확인)

수정 탭에서 고칠 수 없는 부분

제2조(계약기간), 제6조(근로시간·휴게시간 표)처럼 정규직/계약직 체크, 격주 여부 등 조건에 따라 모양이 바뀌는 조항은 코드에 고정되어 있어 이 화면에서 수정할 수 없습니다. 문구 자체를 바꾸고 싶다면 개발자에게 요청해 주세요.

11. 구글 시트 직접 열어보는 법

Apps Script 웹앱(계약서 화면)과는 별개로, 이 시스템이 데이터를 저장하는 원본 구글 스프레드시트 파일이 따로 있습니다.

  • 구글 드라이브에서 이 프로젝트용으로 만들어둔 스프레드시트 파일을 찾아 평소처럼 열면 됩니다(파일 이름을 모르면 개발자에게 한 번만 물어보고, 이후엔 즐겨찾기 해두세요).
  • 또는 Apps Script 편집기에 들어가 있다면, 편집기 좌측 "개요" 또는 상단에서 연결된 스프레드시트로 바로 이동할 수 있습니다.

12. 시스템을 다른 구글 계정으로 복사하기

다른 회사·다른 계정용으로 이 시스템을 똑같이 쓰고 싶다면 가능합니다. 구글시트의 "파일 → 사본 만들기"로 복사하면, 시트 데이터뿐 아니라 거기 바인딩된 Apps Script 프로젝트(Code.gs, Index.html, Seals.html)까지 통째로 함께 복사됩니다.

사본 만들기 순서

  1. 원본 스프레드시트를 열고 상단 파일 → 사본 만들기
  2. 저장 위치를 새 계정의 구글 드라이브로 지정합니다 (또는 원본을 새 계정에 "공유"한 뒤, 그 계정으로 로그인한 상태에서 사본을 만듭니다)

13. 자주 묻는 문제 / 셀프 해결법 (FAQ)

발송 버튼을 눌렀는데 일부만 실패했다고 떠요.

"발송큐" 시트에서 해당 근로자 행을 찾아 "상태"와 "실패사유" 열을 확인하세요. 문자 실패는 대부분 발신번호 미등록·잔액 부족, 이메일 실패는 주소 오타인 경우가 많습니다. 사유 확인 후 작성 탭에서 정보를 고쳐 다시 발송하면 됩니다.

직인이 안 찍히고 경고가 떠요.

경고 메시지에 구체적 사유가 함께 나옵니다. 가장 흔한 경우는 "회사설정" 시트의 법인명과 Seals.html에 등록된 이름이 글자 하나까지 안 맞는 경우입니다(예: (주) vs ㈜). 법인명 표기를 통일하거나, Seals.html 쪽 이름을 맞춰달라고 개발자에게 요청하세요.

직인 크기나 위치를 조금 바꾸고 싶어요.

디자인 조정(크기·위치·색 등)은 코드 수정이 필요해 개발자 문의가 필요합니다.

근로자가 서명했다는데 승인할 화면이 안 보여요.

관리자에게 자동 알림이 가지 않는 구조입니다. "승인대기" 시트를 새로고침해서 직접 확인해야 합니다. 근로자 이름으로 그 시트에서 검색해 보세요. 안 보이면 근로자가 실제로 제출을 마치지 못했을 가능성이 있습니다.

계약서 조항 문구를 통째로 바꾸고 싶어요(법 개정 등).

대부분 "수정" 탭에서 직접 가능합니다. 다만 조건부 구조가 있는 제2조·제6조는 수정 탭에서 바뀌지 않으니 개발자에게 요청하세요.

링크를 잘못 보냈어요. 취소하거나 다시 보낼 수 있나요?

현재는 이미 보낸 링크를 강제로 무효화하는 기능은 없습니다. 다시 보내고 싶으면 작성 탭에서 새로 작성해 재발송하면 되고(새 링크가 발급됩니다), 기존 잘못된 링크를 막는 기능이 꼭 필요하면 개발자에게 추가 요청하세요.

한 번에 수십~수백 명을 발송해도 되나요?

가능합니다. 30명 단위로 자동으로 나눠서 몇 분 간격으로 순차 발송되므로 기다리기만 하면 됩니다. 이메일은 구글 계정의 일일 발송 한도에 걸리면 자동으로 다음 날 이어서 발송됩니다.

완료된 계약서를 PDF로 못 받는다는 근로자 문의가 와요.

카카오톡·네이버 등 인앱 브라우저에서 접속했을 가능성이 높습니다. Safari나 Chrome 같은 일반 브라우저로 링크를 다시 열어달라고 안내해 주세요.

관리자 비밀번호를 잊어버렸어요.

"관리" 탭에서 바꾸려면 기존 비밀번호를 알아야 해서, 잊어버리면 화면에서는 복구할 수 없습니다. 개발자에게 요청해 Apps Script 스크립트 속성(ADMIN_PASSWORD_HASH)을 직접 재설정해 달라고 하세요.

14. 셀프 해결 가능 vs 개발자 문의 필요

구분내용
✅ 관리자 직접 가능 계약 법인 추가·수정·삭제, 새 계약서 초기값 변경, 발송 문자·이메일 문구 수정, 조항 문구 수정(제1·3·4·5·7·8·9·10·11조 + 동의서 3종), 발송 실패 사유 확인, 완료 계약서 조회·다운로드, 관리자 비밀번호 변경("관리" 탭), 다른 구글 계정으로 시스템 사본 만들기
🛠 개발자 문의 필요 문자 발송 서비스(Solapi) API 키·발신번호 등록, 직인 이미지 등록·교체(Seals.html 편집), 제2조·제6조처럼 조건부 구조가 있는 조항의 문구·레이아웃 변경, 완료 안내 문구 수정, 화면 디자인(직인 크기 등) 변경, 관리자 비밀번호 분실 시 재설정, 새 기능 추가, 코드 수정 후 재배포
