1.한눈에 보기

① 작성·발송관리자→ ② 본인인증·서명근로자→ ③ 확인·승인관리자→ ④ 완료 안내 자동 발송시스템

관리자가 할 일은 ① 보내기와 ③ 승인하기 두 가지뿐입니다. 근로자가 서명해도 관리자가 승인해야 계약이 끝납니다.

무엇을어디서
계약서 작성·발송, 문구·설정 변경웹앱 주소 → 관리자 비밀번호 입력
진행 상황 확인, 승인 링크, 완료 링크연결된 구글 스프레드시트
코드 붙여넣기·배포·권한 승인관리자가 직접 하지 않습니다(개발 담당 영역).
필요하면 문의: 경영지원팀 이은비
시트뜻관리자가 볼 때
발송큐보낸 문자·메일 기록상태가 FAILED면 실패사유 열 확인
계약대기근로자가 아직 서명 안 함볼 일 거의 없음
승인대기근로자 서명 완료, 승인 기다리는 중매일 확인 → 승인링크 클릭
계약목록승인까지 끝난 완료 계약문서링크로 다시 열기
⚠ 알림이 오지 않습니다. 근로자가 서명해도 관리자에게 알림이 가지 않습니다. 승인대기 시트를 주기적으로 확인하세요.

2.계약서 보내기 — 작성 탭

  1. 웹앱 주소를 열고 관리자 비밀번호를 입력합니다.
  2. 작성 탭에서 아래 항목을 채웁니다. 오른쪽 미리보기에 계약서가 그대로 보입니다.
  3. 맨 아래 발송하기 → 확인.

근로근로계약서 입력 항목

  • 계약 법인, 입사일
  • 계약 형태: 정규직/계약직(기간 선택), 필요하면 수습 적용(기간·수습급여)
  • 근무장소, 담당업무
  • 근로·휴게시간: 주마다 다르면 격주 체크 후 직접 입력

임금임금계약서 입력 항목

  • 공통: 계약 법인, 계약 구분(신규입사/연봉갱신 — 계약목록 '구분' 열에만 기록), 근무지, 계약 작성일, 임금계약기간(시작일을 바꾸면 종료일이 1년 뒤로 자동 계산)
  • 근로자 카드마다 따로: 입사년도, 근로유형, 월지급액
    • 월지급액을 넣으면 해당 근로유형의 임금테이블 시트에서 연봉·시급·기본급·수당이 자동으로 채워집니다.
    • "임금테이블에 없는 금액입니다"가 뜨면 → 임금테이블에 없는 금액 직접 입력을 체크하고 직접 입력합니다. 기본급+연장+야간 합계가 월지급액과 같아야 합니다.
    • 시급이 최저시급보다 낮으면 빨간 경고가 뜹니다(발송은 가능, 한 번 더 확인).
    • 오른쪽 미리보기는 지금 입력 중인 근로자 기준입니다.

근로자 정보 (공통)

  • + 근로자 추가로 한 번에 최대 10명.
  • 카드마다 이메일/문자 선택, 성명, 전화번호(근로자 접속 비밀번호가 됩니다 — 정확히!), 이메일.

3.승인하기 (직인 날인)

  1. 승인대기 시트에서 해당 행의 승인링크를 클릭합니다.
  2. 관리자 비밀번호를 입력하면 근로자가 서명한 계약서가 보입니다.
  3. 내용 확인 후 승인 및 직인 날인 → 확인.

승인하면 자동으로: 직인이 찍히고 → 근로자에게 처음 보낸 방식(문자/이메일)으로 완료 안내가 가고 → 계약목록으로 옮겨지고 → Drive …_완료보관함 폴더에 사본이 저장됩니다.

"직인 없이 저장됩니다"가 뜨면 법인명 표기가 맞지 않는 경우가 대부분입니다 → 9장

4.완료 계약서 보기·다운로드

  • 계약목록 시트의 문서링크를 클릭하면 언제든 다시 열 수 있습니다.
  • 근로자는 완료 안내로 받은 링크, 또는 처음 받은 서명 링크로도 완료본을 볼 수 있습니다.
  • PDF 저장 버튼 → 인쇄 창에서 "PDF로 저장". 직인이 다 뜬 뒤에 버튼이 나타납니다.
  • 열리는 데 오래 걸리면 "잠시만 기다려 주세요"가 뜹니다. 창을 닫지 말고 기다리면 열립니다.
근로자가 PDF 저장이 안 된다고 하면 카카오톡·네이버 앱 안에서 열었을 가능성이 큽니다. Chrome·Safari로 링크를 다시 열도록 안내하세요.

6.메일·문자 발신처 바꾸기

원리 한 줄 요약 메일을 실제로 보내는 계정은 웹앱을 배포한 구글 계정(이하 배포 계정)입니다. 법인별 발신 이메일을 넣으면, 배포 계정이 보내되 받는 사람에게는 그 주소에서 온 것처럼 보입니다(Gmail 별칭).

A. 메인(배포) 계정으로 보내되, 다른 주소로 보이게 하기

예: 배포 계정은 main@gmail.com, 근로자에게는 hr@gmail.com으로 보이게

  1. 배포 계정(main)으로 Gmail 로그인 → 톱니바퀴 → 모든 설정 보기 → 계정 및 가져오기
  2. 다른 주소에서 메일 보내기 → 다른 이메일 주소 추가 → 이름과 hr@gmail.com 입력 → "별칭으로 처리" 체크 유지 → 다음
  3. 인증 메일 보내기 → hr@gmail.com으로 로그인해 확인 링크 클릭(또는 코드 입력)
  4. 웹앱 설정 탭 → 해당 법인 수정 → 발신 이메일에 hr@gmail.com 입력 → 저장

별칭 등록 전에 보내면 발송큐 실패사유에 "…다른 주소에서 메일 보내기에 등록되어 있지 않습니다"가 남습니다. 등록 후 다시 보내기를 하세요.

B. 반대로 — 다른 계정을 배포 계정으로 바꾸기문의: 경영지원팀 이은비

배포·권한 작업이 필요해 경영지원팀 이은비와 함께 진행합니다.

예: 지금은 main이 보내는데, 앞으로 hr 계정이 직접 보내게(메일 한도도 hr 기준)

  1. 스프레드시트를 hr 계정에 편집자로 공유합니다.
  2. hr 계정으로 로그인 → 스프레드시트 → 확장 프로그램 → Apps Script
  3. 8장 권한 승인을 hr 계정으로 진행합니다.
  4. 배포 → 새 배포 → 웹 앱, "다음 사용자 인증 정보로 실행: 나" → 배포
  5. 새 웹앱 주소를 즐겨찾기하고, 설정 탭의 발신 이메일 칸은 비워 둡니다(hr 주소로 그대로 나감).
⚠ 주소가 바뀝니다. 새 배포는 웹앱 주소가 새로 생깁니다. 이미 보낸 링크(서명·승인·완료)는 예전 배포로 연결되므로 예전 배포를 지우지 마세요. 원래 계정(main)이 보이게 하려면 hr 계정에서 A 방법으로 main 주소를 별칭 등록하면 됩니다.

문자 발신번호

  • 설정 탭 → 법인 수정 → 문자 발신번호. 비우면 담당자연락처로 보냅니다.
  • 어떤 번호든 Solapi 콘솔에 발신번호로 등록돼 있어야 실제로 나갑니다.
근로자에게 보이는 연락처는 따로입니다. 문자·메일 본문의 "담당자/전화번호/이메일"은 법인의 담당자 정보가 들어갑니다. 실제 발신 주소·번호와 다르게 둘 수 있습니다.

7.코드 업데이트 반영 (새 버전 배포)문의: 경영지원팀 이은비

개발자에게 새 Code.gs·Index.html을 받았을 때:

  1. Apps Script 편집기에서 각 파일 내용을 전부 지우고 붙여넣기 → 저장(Ctrl+S)
  2. 새 기능이 권한을 요구하면 8장 진행
  3. 배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포
⛔ 3번을 빼먹으면 저장만 되고 실제 웹앱은 예전 코드 그대로 돌아갑니다. "새 배포"가 아니라 기존 배포 수정이어야 주소가 유지됩니다.

8.권한 승인 (권한 검토)문의: 경영지원팀 이은비

언제? 처음 설치할 때, 배포 계정을 바꿨을 때, 업데이트 후 "…을(를) 호출할 수 있는 권한이 없습니다" 오류가 날 때.

  1. 배포 계정으로 로그인한 상태에서 Apps Script 편집기를 엽니다.
  2. 위쪽 함수 선택 목록에서 authorizeServices를 고르고 ▶ 실행.
  3. 권한 검토 → 계정 선택 → "Google에서 확인하지 않은 앱" 화면이 나오면 고급 → (프로젝트명)(으)로 이동(안전하지 않음) → 허용.
  4. 실행 로그에 "권한 승인 완료"가 보이면 끝 → 7장 3번(새 버전 배포).
  5. 실패해서 멈춰 있던 발송은 다시 보내기.
그래도 같은 권한 오류가 나면

프로젝트 설정(톱니바퀴) → "appsscript.json" 매니페스트 파일 표시를 켭니다. appsscript.json에 "oauthScopes" 목록이 있을 때만 아래 항목 중 빠진 것을 추가하고 저장한 뒤 1번부터 다시 하세요(목록이 없으면 건드리지 마세요).

배포 설정의 "다음 사용자 인증 정보로 실행"이 나인지도 확인하세요.

9.문제 해결문의: 경영지원팀 이은비

아래로 해결되지 않으면 발송큐 실패사유나 화면의 오류 문구를 캡처해서 경영지원팀 이은비에게 보내 주세요.

실패한 발송을 다시 보내고 싶어요
  1. 발송큐에서 상태가 FAILED인 칸을 PENDING으로 바꿉니다.
  2. Apps Script 편집기에서 processSendQueue를 ▶ 실행합니다.

근로자 정보(번호·이메일)가 틀렸던 경우는 작성 탭에서 새로 발송하세요.

  • 코드를 바꾼 뒤라면 새 버전 배포를 했는지 확인(7장).
  • 계약목록 시트의 맨 윗줄 이름을 바꾸지 않았는지 확인 — 특히 데이터(JSON), 문서링크는 글자 그대로여야 합니다.
  • 임금편집기에서 diagnoseContract를 실행하면 원인을 로그로 알려줍니다(맨 아래 DIAG_ID에 링크의 id= 값을 넣고 실행).
직인이 안 찍혀요 / 예전 직인이 나와요
  • 경고창의 사유에 나온 법인명과 Seals.html의 이름을 똑같이 맞추세요((주) 표기 통일).
  • 직인을 바꿨는데 예전 것이 나오면 편집기에서 clearSealCache 실행(안 해도 6시간 뒤 자동 반영).
  • 열리는 속도를 높이려면 직인 이미지를 300×300px 정도로 줄여서 넣으세요.
완료 계약서가 늦게 열려요

"잠시만 기다려 주세요"가 보이면 창을 닫지 말고 기다리세요. 처음 한 번은 직인을 읽느라 느리고, 이후에는 빨라집니다.

근로자가 서명했다는데 승인대기에 없어요

근로자가 마지막 최종 제출까지 누르지 않은 경우입니다. 링크를 다시 열어 끝까지 진행하도록 안내하세요(계약대기에 남아 있으면 미제출).

링크를 잘못 보냈어요

보낸 링크를 취소하는 기능은 없습니다. 작성 탭에서 올바른 내용으로 새로 발송하면 새 링크가 나갑니다.

관리자 비밀번호를 잊었어요

Apps Script 편집기 → 프로젝트 설정 → 스크립트 속성에서 ADMIN_PASSWORD_HASH를 삭제하면 초기 비밀번호로 돌아갑니다(초기 비밀번호는 개발자에게 문의). 접속 후 바로 관리 탭에서 바꾸세요.

10.하면 안 되는 것

  • 시트 맨 윗줄(머리말) 이름 바꾸기 — 특히 계약목록·발송큐. 열 순서는 바꿔도 되지만 이름은 그대로.
  • ID·상태·데이터 칸 직접 수정 — 다시 보내기용 FAILED → PENDING 변경만 예외.
  • 승인대기·계약목록 행 삭제 — 해당 계약 링크가 영영 안 열립니다.
  • 예전 배포 삭제 — 이미 보낸 링크가 끊깁니다.
  • 웹앱 주소·관리자 비밀번호 외부 공유.
